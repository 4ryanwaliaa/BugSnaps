# PhishLens offline evaluation

`node scripts/evaluate-phishing-detector.cjs <phishtank.json> <comparison.txt>`

Alternatively, `node scripts/evaluate-phishing-detector.cjs --listed-urls <threat-list.txt-or-json> [comparison.txt]` accepts an independent threat-list sample as a text file with one URL or hostname per line, or a JSON array of strings. It does not verify that those listings are active or correct; record the source and methodology.

This runs the current local URL-pattern engine on two supplied samples without making any network request or printing the URLs. In the first form, the first file must be a JSON array of PhishTank entries with a `url` and `verified` / `online` set to `yes` or `true`. Entries missing either status are excluded. The second file is a UTF-8 list of comparison URLs or domains, one per line, with optional `#` comments. Keep both samples outside this public repository: phishing feeds can contain live malicious links and URLs may include tokens. Do not open those links.

The report includes SHA-256 hashes of both inputs and the engine, the date, duplicate counts, invalid-input counts, verdict counts and counts for each finding. It rejects exact input overlap between samples. It outputs counts rather than claiming a general accuracy percentage. Review which warnings drive results and inspect a representative sample in a controlled environment.

PhishTank documents [downloadable feeds](https://phishtank.org/developer_info.php) of community-verified phishing URLs. The online-valid feed changes hourly and has selection bias; save a timestamped snapshot and keep its hash for reproducibility. Follow its usage limits and [terms](https://phishtank.org/terms.php); automated frequent retrieval needs an application key. Do not treat a PhishTank snapshot as all current phishing URLs.

A comparison list must be chosen and documented carefully. A popular-domain ranking does **not** establish that a URL is benign; popular domains can host malicious content, and homepage-only samples do not represent the paths and redirects people receive. Check permissions for each source: for example, the default [Tranco ranking](https://tranco-list.eu/) incorporates a source marked CC BY-NC. Don't assume that dataset is cleared for commercial use. The script deliberately calls the second sample “comparison,” not “benign.”

For a meaningful evaluation, independently label a diverse comparison set, split by time and registered domain so related URLs don't cross development and test sets, retain a newer untouched holdout, document source, collection time, selection, duplicate handling and any label uncertainty, and report results separately by source and category. Evaluate the same endpoint and options users actually receive. Exact-input overlap checking alone does not prevent domain/campaign overlap. Compare flag rates for phishing and trusted labels with uncertainty intervals, rather than inferring real-world prevalence or universal accuracy. Local pattern results cannot validate a separate external reputation lookup. A synthetic fixture or a small convenience sample is suitable for regression testing only.

## Example evaluation: 28 October 2026

A local, offline run used the [PhishDestroy DNS-active domain list](https://github.com/phishdestroy/destroylist/blob/2202d4cbb9cd17297fa839a874c0a456943ba1b6/dns/active_domains.json) (file commit 2026-10-27 21:10 UTC, SHA-256 `ad266435286aebbaefb33a935952158165aed6121053e3c0e0f083e009597a7d`) and engine SHA-256 `05a241ae129df9c4dd06ee0807a49fbcf4d4e71be814167ffe39321ff3e5a583`. The project [describes](https://phishdestroy.io/dataset) its list as phishing, crypto-drainer and scam domains; its DNS-active category means DNS resolved at the last check, not that the phishing page is currently reachable. The provider says the data may be used commercially but notes inconsistencies among its published licence statements; the source repository identifies an MIT licence. Verify the applicable terms before redistributing data.

Of 141,480 unique hostnames supplied, all parsed; 175 produced high-concern results, 6,361 review results and 134,944 no-obvious-signals results. No comparison set was evaluated and no target domains were contacted. This shows the lexical checker misses many entries in this particular provider-labelled list. It does not measure live-feed lookup, overall detection accuracy, false-positive rates or performance on full URLs, and the list's distribution and labels may not represent real-world traffic. Re-run against a dated snapshot and independently labelled holdout for useful comparisons.
